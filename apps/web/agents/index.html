An agent that wants to buy a tokenized stock is the one party that shouldn't grade its own order. Stamp gives it the same ticket a person gets - same code, same hash - over HTTP, MCP, or a paid x402 route.

http · freePOST /v1/ticketsThe API this page runs on. JSON in, ticket out. No key, no account.
mcp · freestamp_ticket · stamp_verifyTwo read-only tools on a BNB Agent Studio agent. Decide an order; recompute a hash.
x402 · $0.02POST /x402The same ticket behind a payment challenge. B402 verifies and settles before the work runs.

Over HTTP

curl -s https://stamp-iizn.onrender.com/v1/tickets \
  -H 'content-type: application/json' \
  -d '{"intent":"Buy 1 NFLX","policy":{"issuer":"ondo"}}'

Returns { ticket, verify }. Act on ticket.verdict === "ALLOW" only. Full reference in http api.

Over MCP

{
  "mcpServers": {
    "stamp": { "url": "http://localhost:8000/mcp" }
  }
}

Run the agent with bag dev from agent/, then call stamp_ticket with {"intent":"Buy $20 of NVIDIA"}. Setup in agent studio face.

Paying over x402

bag x402 buy https://<agent-host>/x402 --method POST \
  --json '{"prompt":"Buy $20 of NVIDIA"}' \
  --max-usd 0.05 --asset USDT

The body comes back as {"result": "<ticket JSON>"}. Its verifyUrl opens on proof, where anyone can recompute the hash.

What the agent will not do

  • Run an LLM anywhere in the verdict. The provider is set to none.
  • Re-implement a check. It calls the Stamp API; the engine decides.
  • Sign a trade. Its wallet only receives the $0.02 and signs its own identity.
  • Pretend a paid call is free: payment settles before the work, so try the order on MCP first.
