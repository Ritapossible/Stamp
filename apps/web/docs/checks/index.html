Checks & reason codes

Checks run in a fixed order and stop at the first BLOCK. WARN codes pile up. The verdict is BLOCK if anything blocked, otherwise WARN if anything warned, otherwise ALLOW. The code lives in packages/engine/src/verdict.ts - the only place a verdict is made.

Decision checks

#checkcodesresult
1Parse the order with a fixed grammar. No model.UNPARSEABLE_INTENTBLOCK
2Find the token on chain 56 by symbol, company name or ticker. Buy only the policy issuer; list the rest as not the same instrument.UNKNOWN_TOKEN AMBIGUOUS_QUERY AMBIGUOUS_ISSUER ISSUER_NOT_ALLOWEDBLOCK
3Complete data: a price, a status, a documented reasonCode. data: null after one retry counts as missing.INCOMPLETE_STATUSBLOCK
4A multiplier exists and is above zero.NO_MULTIPLIERBLOCK
5List and live multipliers agree. 2× apart or more is a conflict; a smaller gap is drift (a note for xStock, whose list lags).MULTIPLIER_CONFLICT MULTIPLIER_DRIFTBLOCK · WARN
6A bare number with a multiplier other than 1 has two readings. Both are shown.UNIT_AMBIGUOUSBLOCK
7Halts: corporate actions, market pauses (including Binance's 20:00 close pause), a closed venue.HALTED_CORPORATE_ACTION MARKET_HALTED VENUE_CLOSEDBLOCK
8Session from Binance, cross-checked against the New York clock.SESSION_DISAGREEMENT SESSION_UNKNOWNWARN
9A reference price: the live stock price, a sibling's live stock price, or Stamp's recorded close.NO_REFERENCEWARN
10More than 5% off the reference either way is a data error.PRICE_IMPLAUSIBLEBLOCK
11Premium above the policy limit (0.30% in cash hours, 0.80% otherwise).SESSION_RICHWARN
12A discount past the 0.10% noise band. Size is never increased.THIN_BOOKnote
13$20 an order, $50 a day of filled orders.OVER_CAPBLOCK
14Everything passed.OKALLOW

Notes (THIN_BOOK, xStock MULTIPLIER_DRIFT) never change the verdict. Rejected siblings carry NEVER_SWITCH.

The unit math, on every ticket

token units   = dollars / token price
shares        = token units × multiplier
price / share = token price / multiplier     (Binance's formula, cited on the ticket)
premium (bps) = round((price per share - reference) / reference × 10000)

Execution checks

These run only after an ALLOW, when you press review & sign. Stamp gets a fresh quote from the Binance Trading API and checks it against the decision before your wallet sees anything.

#checkblocks with
E1The decision re-hashes to its stored hash; the policy matches its hash.TICKET_TAMPERED
E1bThe decision is ALLOW, never WARN.DECISION_NOT_ALLOWED
E2The decision is at most 120 s old.DECISION_STALE
E4The quote is at most 25 s old.QUOTE_STALE
E5The quote buys the decision's token with BSC USDT.ISSUER_MISMATCH
E5bThe quote spends the decision's dollars (±$0.01).AMOUNT_MISMATCH
E6Quoted price within 0.50% of the decision's price.SLIPPAGE
E7SWAP: the transaction is from you, sends no BNB, and simulation shows you gain the chosen token and no sibling. RFQ: the typed data names the token, amount and you.TX_MISMATCH SIMULATION_FAILED SIMULATION_MISMATCH TYPED_DATA_MISMATCH
E8USDT allowance short: an exact-amount approval comes first, then a fresh review.APPROVAL_REQUIRED

Binance returned SWAP mode (a normal transaction) for tokenized stocks from Frankfurt, not the RFQ typed-data flow its docs describe. Stamp handles both.
