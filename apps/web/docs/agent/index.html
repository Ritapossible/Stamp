Agent Studio face

The agent/ folder is a BNB Agent Studio project, scaffolded by bag init. It gives other agents the same ticket a person gets, free over MCP, and at $0.02 per call over x402 once Binance approves its B402 merchant.

faceinput → outputprice
MCP stamp_ticket{ intent, issuer? } → the ticketfree
MCP stamp_verify{ hash } → { matches, verdict, reasons }free
POST /x402{"prompt":"Buy $20 of NVIDIA"} → {"result":"<ticket JSON>"}$0.02, B402
ERC-8004on-chain identity pointing at /mcp (registered at deploy)gas

The agent calls the Stamp API; it does not re-implement a check, and no LLM runs on any path. Its wallet never signs a trade - it only receives payment and signs its own identity.

Run it locally

npm i -g @bnbagent/studio-cli     # the bag CLI
corepack enable && cd agent && pnpm install
(cd app/agent && bag wallet new --generate-password)   # throwaway testnet key
STAMP_API_URL=https://stamp-iizn.onrender.com bag dev  # http://localhost:8000/mcp

Until a B402 merchant exists for the agent's wallet, POST /x402 answers 503 x402 rail dormant. Nobody can pay, and nothing else breaks.

Turn on payments

  1. bag wallet show - the address that receives the $0.02.
  2. Apply for a B402 merchant for that exact wallet. Approval is manual.
  3. Put the four B402_* values in agent/.studio/.env.local with an editor. Never in a chat, commit or command line.
  4. bag doctor, then bag dev. /x402 now answers 402 with a payment challenge.

Deploy and register

bag deploy --provider bnb        # managed trial: BSC testnet, 48 hours
bag erc8004 register --protocol MCP --name stamp \
  --description "Pre-trade gate for tokenized stocks on BSC"

For something that outlives 48 hours, bag deploy --provider aws | azure | nodeops deploys to your own cloud.

In front of the Binance Agentic Wallet

Agents that trade through Binance's Agentic Wallet (baw, skill binance-agentic-wallet) can put Stamp in front of every tokenized-stock buy. The wallet builds and signs the swap itself, under the limits you set in the Binance App, so Stamp checks what it can see: the quote before and the chain after.

npm i -g @binance/agentic-wallet
baw auth signin                     # confirm in the Binance App
npm run agentic -- "Buy $20 of NVIDIA" --dry-run
npm run agentic -- "Buy $20 of NVIDIA"
  1. Stamp decides. Anything but ALLOW stops here, and baw is never called.
  2. baw market-order quote for the ticket's contract address and dollars. The execution ticket checks the quoted token symbol, the dollars, the price (0.50%) and the age.
  3. You type yes. Stamp quotes and checks again, because the decision is only good for 120 s.
  4. baw market-order swap with --slippage 0.5, then polls until FINISHED or FAILED. An order id is not a fill.
  5. The fill ticket reads the BSC receipt: the ticket's token must arrive, no sibling issuer's token may arrive, and the price paid must be within policy.

The quote does not bind the swap - that is how baw works - which is why the fill is checked. Agents that can't run the script follow the same rule by hand from skills/stamp-gate/SKILL.md ↗.

Pay it from another agent

bag x402 buy https://<agent-host>/x402 --method POST \
  --json '{"prompt":"Buy $20 of NVIDIA"}' --max-usd 0.05 --asset USDT

Payment settles before the work runs, so the agent checks first: an empty or malformed prompt, an order Stamp's grammar can't read, or a Stamp server that's down gets a free 400 or 503 with "charged": false, and no payment is asked for. Paid replay records live in a file (B402_REPLAY_FILE, default .stamp-data/b402-replay.json), so a restart can't accept the same payment twice.
